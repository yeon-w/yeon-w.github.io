## 1. 서론: 연구 배경과 문제의식

### 1.1 LLM 에이전트와 Agent Skill의 발전

최근 LLM 기반 에이전트는 단순한 질문·응답을 넘어 파일을 관리하고, 코드를 실행하고, 외부 서비스와 상호작용하는 등 다양한 작업을 수행할 수 있게 되었다.

이러한 기능을 확장하는 방법 중 하나가 Agent Skill이다.

Agent Skill은 에이전트가 특정 작업을 수행하는 데 필요한 지침과 실행 코드를 하나의 패키지로 제공하는 방식이다.

일반적으로 다음과 같은 구성 요소를 포함한다.

- **Metadata:** Skill의 이름, 설명, 사용 조건 등을 정의한다.
- **Instructions:** `SKILL.md`와 같은 파일을 통해 작업 수행 절차를 자연어로 설명한다.
- **Code:** 실제 작업을 수행하는 Python, Shell 등의 실행 스크립트를 포함한다.

예를 들어 GitHub 저장소를 분석하는 Skill이라면 저장소를 복제하고, 최근 커밋을 분석하고, 보안상 중요한 변경 사항을 요약하도록 구성할 수 있다.

이러한 Skill은 에이전트의 기능을 쉽게 확장할 수 있다는 장점이 있지만, 동시에 새로운 보안 문제를 발생시킨다.

### 1.2 Agent Skill의 과도한 권한 사용 문제

Agent Skill의 주요 보안 문제 중 하나는 사용자가 요청한 작업 범위를 벗어나는 행동을 수행할 수 있다는 것이다.

예를 들어 사용자가 에이전트에 다음과 같이 요청했다고 가정하자.

"최근 GitHub 커밋을 분석해서 위험한 변경 사항을 요약해 줘."

이 요청을 수행하기 위해 필요한 작업은 저장소 접근, 커밋 정보 확인, 변경 사항 분석 정도이다.

그러나 Skill 내부에 다음과 같은 추가 절차가 포함되어 있을 수 있다.

- 로컬 환경 설정 파일 수집
- 사용자 명령어 기록 확인
- 분석 결과를 외부 서버로 전송

이러한 작업은 저장소 분석이라는 기능과 어느 정도 관련되어 보일 수 있지만, 사용자가 요청한 작업을 완료하는 데 반드시 필요한 것은 아니다.

문제는 에이전트가 Skill의 지침을 신뢰하고 실행할 경우 사용자가 명시적으로 허가하지 않은 행동까지 수행할 수 있다는 점이다.

이러한 문제는 최소 권한 원칙(Principle of Least Privilege)과 관련된다.

최소 권한 원칙은 시스템의 구성 요소가 작업을 수행하는 데 필요한 최소한의 권한만 사용해야 한다는 보안 설계 원칙이다.

### 1.3 기존 Skill 보안 분석의 한계

기존의 Agent Skill 보안 도구는 주로 악의적인 Skill을 탐지하는 데 집중하였다.

예를 들어 Skill의 코드에 민감한 파일을 읽는 기능이나 외부 서버로 데이터를 전송하는 기능이 포함되어 있다면 위험한 Skill로 분류할 수 있다.

그러나 이러한 접근에는 한계가 있다.

**동일한 행동이라도 사용자 요청에 따라 정상적인 행동이 될 수도 있고, 과도한 권한 사용이 될 수도 있기 때문이다.**

예를 들어 사용자가 분석 결과를 외부 서버로 전송하라고 명시적으로 요청했다면 네트워크 전송은 필요한 작업일 수 있다.

반면 사용자가 단순히 로컬에서 결과를 확인하려는 상황이라면 동일한 전송 행동은 불필요할 수 있다.

따라서 특정 Skill이 악의적인지 여부만 판단하는 방식으로는 최소 권한 위반을 정확하게 탐지하기 어렵다.

저자들은 이러한 문제를 해결하기 위해 SkillScope를 제안하였다.

## 2. 문제 정의와 연구 목표

본 논문은 **Agent Skill이 실제 사용자 요청을 수행하는 과정에서 불필요하거나 허가되지 않은 행동을 실행하는지 탐지하고, 해당 행동을 제한하면서 정상적인 기능은 유지하는 것**을 목표로 한다.

이를 위해 세 가지 문제를 해결해야 한다.

### 2.1 Skill의 실제 행동을 어떻게 분석할 것인가?

Agent Skill의 행동은 단일 코드 파일에만 정의되어 있지 않다.

일부 작업은 `SKILL.md`의 자연어 지침으로 정의되며, 다른 작업은 Python이나 Shell 스크립트로 구현된다.

또한 자연어 지침에서 스크립트를 호출하고 해당 결과를 다른 작업에 사용하는 등 여러 구성 요소가 연결될 수 있다.

따라서 자연어 지침과 실행 코드를 함께 분석할 수 있는 방법이 필요하다.

### 2.2 특정 행동이 과도한 권한 사용인지 어떻게 판단할 것인가?

Skill에 민감한 파일을 읽는 기능이 존재한다는 사실만으로 최소 권한 위반이라고 판단할 수는 없다.

현재 사용자 요청이 해당 파일의 분석을 요구한다면 정당한 접근일 수 있기 때문이다.

따라서 개별 행동이 사용자에게 허가되었는지, 작업을 완료하는 데 필요한지 판단해야 한다.

### 2.3 불필요한 행동을 제거하면서 정상 기능을 유지할 수 있는가?

위험한 행동을 모두 삭제하면 보안성이 높아질 수 있지만, 정상적인 사용자 작업까지 수행하지 못하게 될 수 있다.

따라서 위험한 기능을 무조건 제거하기보다 **사용자 요청에 따라 필요한 경우에만 실행되도록 제어하는 방식**이 필요하다.

## 3. 핵심 아이디어: SkillScope

SkillScope는 Agent Skill의 자연어 지침과 실행 코드를 하나의 그래프로 표현하고, 개별 행동이 사용자 요청의 권한 범위에 포함되는지 검증하는 프레임워크이다.

핵심 아이디어는 다음과 같다.

**Skill 자체를 안전하거나 악의적인 것으로 분류하는 대신, Skill이 수행하는 각각의 행동이 현재 작업에 허가되고 필요한지를 검증한다.**

이를 위해 SkillScope는 세 가지 구성 요소를 제안한다.

### 3.1 Unified Execution Graph

첫 번째는 Skill의 동작을 통합 실행 그래프로 표현하는 것이다.

SkillScope는 `SKILL.md`의 자연어 절차와 실행 스크립트의 코드 연산을 각각 Action Node로 변환한다.

예를 들어 다음과 같은 작업을 생각할 수 있다.

`Read Repository → Analyze Commits → Read Environment File → Send Report`

이 중 저장소를 읽고 커밋을 분석하는 행동은 사용자 요청에 필요한 작업일 수 있다.

반면 환경 설정 파일을 읽거나 외부로 전송하는 행동은 사용자 요청에 따라 과도한 권한 사용이 될 수 있다.

SkillScope는 이러한 행동을 개별 노드로 분리하고, 노드 사이의 실행 순서와 데이터 의존관계를 그래프로 표현한다.

이를 통해 어떤 행동이 어떤 조건에서 실행되는지 분석할 수 있다.

### 3.2 Task-conditioned Over-privilege Validation

두 번째는 사용자 요청을 기준으로 개별 행동의 필요성과 권한을 검증하는 것이다.

SkillScope는 두 가지 기준을 사용한다.

**① Authorization**

해당 행동이 사용자의 요청에 의해 허가되었는지 확인한다.

예를 들어 사용자가 외부 전송을 요청하지 않았다면 외부 서버에 데이터를 전송하는 행동은 허가 범위를 벗어날 수 있다.

**② Necessity**

해당 행동을 수행하지 않아도 사용자가 요청한 작업을 완료할 수 있는지 확인한다.

예를 들어 환경 설정 파일을 읽는 동작을 제거해도 커밋 분석 결과가 정상적으로 생성된다면 해당 동작은 불필요할 수 있다.

논문에서 과도한 권한 사용은 다음과 같이 정의된다.

`OverPrivileged = Unauthorized OR Unnecessary`

즉, 보안상 중요한 행동이 사용자에게 허가되지 않았거나 작업 완료에 필요하지 않다면 최소 권한 위반 후보가 된다.

이 기준은 단순히 위험한 함수를 탐지하는 기존 방식과 차이가 있다.

### 3.3 Control-flow Privilege Constraining

세 번째는 탐지된 과도한 권한 사용을 제한하는 것이다.

SkillScope는 위험한 행동을 무조건 삭제하지 않는다.

대신 해당 행동을 실행하기 전에 사용자 요청에 따른 조건을 확인하도록 실행 흐름을 수정한다.

예를 들어 외부 전송 기능이 포함된 Skill이라면 사용자가 명시적으로 전송을 요청한 경우에만 해당 기능을 실행하도록 제어할 수 있다.

이를 통해 정상적인 기능을 유지하면서도 불필요한 권한 사용을 줄이는 것이 목표이다.

## 4. 방법론 및 시스템 구성

SkillScope는 크게 세 가지 단계로 구성된다.

### 4.1 Over-Privilege Candidate Extraction

첫 번째 단계는 과도한 권한 사용이 발생할 가능성이 있는 행동을 탐색하는 것이다.

#### ① Unified Execution Graph Construction

SkillScope는 자연어 지침과 코드의 동작을 하나의 그래프에 통합한다.

각 Action Node는 다음 정보를 포함한다.

- 행동이 정의된 위치
- 수행하는 연산의 유형
- 연산의 대상 객체

예를 들어 특정 보고서를 외부로 전송하는 자연어 지침은 다음처럼 표현할 수 있다.

`<instruction, send, report>`

또한 SkillScope는 행동 사이의 관계를 나타내기 위해 네 가지 유형의 Edge를 사용한다.

- **Control Edge:** 실행 순서 및 조건 관계
- **Data Edge:** 데이터 전달 관계
- **Call Edge:** 자연어 지침에서 스크립트를 호출하는 관계
- **Return Edge:** 스크립트 실행 결과가 후속 행동으로 전달되는 관계

이러한 그래프는 자연어 지침과 실제 코드 사이의 연결 관계를 분석할 수 있게 한다.

#### ② Over-Privilege Candidate Classification

다음으로 Skill의 설명과 실행 그래프를 비교하여 과도한 권한 사용 가능성이 있는 행동을 추출한다.

예를 들어 Skill의 목적이 로컬 문서 요약인데 외부 서버로 데이터를 전송하는 노드가 있다면 이를 잠재적인 과도 권한 사용 후보로 분류할 수 있다.

다만 이 단계에서는 실제 최소 권한 위반 여부를 확정하지 않는다.

사용자 요청에 따라 행동의 정당성이 달라질 수 있기 때문이다.

따라서 SkillScope는 의심스러운 행동을 우선 탐색한 뒤 다음 단계에서 실제 실행을 통해 검증한다.

### 4.2 Action Over-Privilege Validation

두 번째 단계는 추출한 행동이 실제로 불필요하거나 허가되지 않은 행동인지 확인하는 것이다.

#### ① Graph-guided Task Generation

SkillScope는 통합 실행 그래프를 활용하여 Skill이 수행할 수 있는 다양한 작업 시나리오를 생성한다.

예를 들어 저장소 분석 Skill이라면 다음과 같은 요청을 생성할 수 있다.

- 최근 커밋 요약
- 보안상 위험한 변경 사항 분석
- 분석 보고서 생성
- 보고서 외부 전송

이러한 요청은 단순히 무작위로 생성되는 것이 아니라 실행 그래프의 행동 경로를 기준으로 생성된다.

따라서 특정 행동을 실행할 가능성이 있는 사용자 요청을 체계적으로 탐색할 수 있다.

#### ② Runtime Replay Execution

이후 SkillScope는 동일한 사용자 요청을 두 가지 조건에서 실행한다.

**Original Execution**

원래 Skill을 변경하지 않고 실행한다.

**Replay Execution**

검증 대상 행동을 제거하거나 비활성화한 상태에서 동일한 요청을 다시 실행한다.

예를 들어 로컬 저장소 분석 과정에서 외부 데이터 전송 기능이 실행되었다고 가정하자.

SkillScope는 외부 전송 기능을 비활성화한 상태에서 작업을 다시 실행한다.

이때 커밋 분석과 보고서 생성이 정상적으로 수행된다면 외부 전송은 해당 작업에 불필요한 행동일 가능성이 높다.

SkillScope는 원본 실행과 Replay 실행의 결과 및 실행 기록을 비교하여 행동의 필요성을 판단한다.

이 과정에는 LLM 기반 판단도 사용된다.

단, 단순히 최종 출력 문자열이 동일한지만 비교하는 것은 아니다. 사용자가 요청한 핵심 기능과 필요한 부작용이 유지되는지도 함께 확인한다.

이를 통해 행동의 필요성을 실행 결과에 기반하여 평가한다.

### 4.3 Control-flow Privilege Constraining

세 번째 단계는 검증된 과도 권한 사용 행동을 제한하는 것이다.

SkillScope는 통합 실행 그래프에 조건부 제어 노드를 추가한다.

기존 실행 흐름이 다음과 같다고 가정하자.

`Generate Report → Send Report`

SkillScope는 이를 다음과 같이 수정한다.

`Generate Report → Check Task Authorization → Send Report (if authorized)`

이후 변경된 실행 흐름을 실제 Skill 파일에 반영한다.

자연어 지침에서 발생하는 문제는 `SKILL.md`의 작업 수행 조건을 수정한다.

코드에서 발생하는 문제는 실행 로직을 분리하거나 조건부 실행 구조로 변경한다.

이러한 접근의 장점은 위험한 기능을 완전히 제거하지 않는다는 것이다.

사용자가 실제로 해당 기능을 요청한 경우에는 정상적으로 사용할 수 있도록 유지하면서, 불필요한 실행만 제한할 수 있다.

다만 자연어 지침에 추가한 제약은 에이전트가 이를 올바르게 따르는 것에 영향을 받으므로 운영체제 수준의 강제 접근 제어와 동일한 보장을 제공하는 것은 아니다.

## 5. 실험 및 평가

저자들은 SkillScope의 성능을 검증하기 위해 실제 Agent Skill 생태계에서 수집한 데이터와 수동으로 검증한 평가 집합을 사용하였다.

### 5.1 과도 권한 사용 탐지 성능

SkillScope는 과도한 권한 사용이 포함된 Skill 100개와 정상 Skill 100개로 구성된 평가 집합에서 탐지 성능을 측정하였다.

| 평가 항목 | 결과 |
|---|---:|
| 평가 대상 Skill | 200개 |
| True Positive | 95 |
| False Positive | 6 |
| True Negative | 94 |
| False Negative | 5 |
| Precision | 94.06% |
| Recall | 95.00% |
| F1 Score | 94.53% |

SkillScope는 Skill 단위에서 94.53%의 F1 Score를 기록하였다.

또한 개별 행동 단위에서는 94.74%, 특정 사용자 작업과 행동의 조합인 Action-in-Task 단위에서는 93.28%의 F1 Score를 기록하였다.

이는 Skill 전체의 위험 여부뿐 아니라 어떤 행동이 어떤 사용자 요청에서 문제가 되는지까지 비교적 정확하게 분석할 수 있음을 보여준다.

### 5.2 실제 Skill 생태계 분석

저자들은 공개 Skill 저장소와 마켓플레이스에서 총 110,046개의 Skill을 수집하였다.

이후 중복되거나 유효하지 않은 항목을 제외한 68,312개의 Skill을 분석하였다.

그 결과 6,590개의 Skill에서 과도한 권한 사용 행동이 검증되었다.

이는 분석한 Skill의 약 9.6%에 해당한다.

다만 이 수치는 해당 데이터셋과 검증 방법에서 확인된 결과이며, 모든 Agent Skill의 최소 권한 위반 비율을 의미하지는 않는다.

저자들은 검증된 행동을 두 가지 유형으로 구분하였다.

**① Over-collection**

사용자 요청에 필요한 범위를 넘어 민감한 정보를 읽거나 과도하게 데이터를 수집·전송하는 행동이다.

**② Over-execution**

사용자 요청에 필요하지 않은 명령어 실행, 코드 실행, SQL 실행 등의 행동이다.

검증된 Skill 가운데 Over-execution은 약 55.1%, Over-collection은 약 44.9%를 차지하였다.

이는 Skill의 보안 문제가 단순한 정보 유출에 한정되지 않고 불필요한 시스템 기능 실행까지 포함한다는 점을 보여준다.

### 5.3 최소 권한 제어 효과

저자들은 탐지된 과도 권한 사용 행동을 제한한 이후 실제 실행 결과가 어떻게 달라지는지 측정하였다.

| 평가 항목 | 제어 전 | 제어 후 |
|---|---:|---:|
| 과도 권한 사용 Skill | 95개 | 13개 |
| 과도 권한 사용 Action | 279개 | 31개 |
| 과도 권한 사용 Action-in-Task | 472개 | 54개 |

Action-in-Task 기준 과도 권한 사용 발생 횟수가 **88.56% 감소**하였다.

이는 SkillScope가 위험한 행동을 탐지하는 것뿐 아니라 실제 실행 과정에서 해당 행동을 상당 부분 제한할 수 있음을 보여준다.

또한 정상적인 작업 249개를 대상으로 평가한 결과, SkillScope로 수정한 Skill은 249개 작업을 모두 완료하였다.

반면 위험한 행동을 단순히 삭제하는 방식에서는 249개 중 144개 작업만 완료되었다.

이 결과는 **위험한 기능을 무조건 제거하는 것보다, 사용자 작업의 맥락에 따라 실행 여부를 결정하는 방식이 정상 기능을 유지하는 데 유리하다**는 점을 보여준다.

다만 작업 완료율이 100%였다고 해서 모든 실행 결과가 이전과 완전히 동일했던 것은 아니다. 출력 동등성은 94.78%, 핵심 실행 경로의 동등성은 93.17%로 측정되었다.

### 5.4 기존 연구와의 비교

저자들은 SkillScope를 기존 Skill 보안 탐지 도구와 비교하였다.

| 탐지 도구 | F1 Score |
|---|---:|
| Skill Scanner | 78.26% |
| Caterpillar | 61.08% |
| MalSkills | 86.87% |
| SkillScope | 94.53% |

SkillScope는 비교 대상 도구보다 높은 F1 Score를 기록하였다.

기존 도구가 주로 악의적인 패턴이나 의심스러운 코드의 존재를 탐지하는 데 집중했다면, SkillScope는 구체적인 사용자 작업을 생성하고 실제 실행 결과를 검증한다는 차이가 있다.

따라서 단순히 위험해 보이는 기능이 존재한다는 이유로 Skill을 악의적으로 분류하는 문제를 줄일 수 있었다.

### 5.5 Ablation Study

저자들은 주요 구성 요소의 효과를 확인하기 위해 Ablation Study를 수행하였다.

| 실험 구성 | F1 Score |
|---|---:|
| 전체 SkillScope | 94.53% |
| Unified Graph 제거 | 73.74% |
| Graph-guided Task Generation 제거 | 82.16% |
| Dynamic Validation 제거 | 79.22% |

가장 큰 성능 감소는 Unified Graph를 제거했을 때 발생하였다.

이는 Skill의 자연어 지침과 코드를 하나의 실행 그래프로 모델링하는 과정이 탐지 성능에 중요하다는 점을 보여준다.

또한 Dynamic Validation을 제거했을 때에도 성능이 감소하였다.

이는 코드나 지침의 내용만으로 최소 권한 위반을 판단하는 것보다 실제 실행 결과를 함께 분석하는 방식이 더 정확할 수 있음을 의미한다.

## 6. 한계점 및 아쉬운 점

### 6.1 LLM의 비결정적인 실행 결과

SkillScope는 원본 Skill과 수정된 Skill을 각각 실행하여 결과를 비교한다.

그러나 LLM 에이전트는 동일한 프롬프트를 전달하더라도 실행 경로나 최종 출력이 달라질 수 있다.

따라서 두 실행 사이의 차이가 특정 행동을 제거했기 때문인지, LLM의 비결정적인 동작 때문인지 구분하기 어려운 경우가 있다.

이러한 문제는 검증 결과의 정확성과 재현성에 영향을 줄 수 있다.

### 6.2 복잡한 코드 구조에서의 권한 제어

SkillScope는 과도한 권한 사용 행동을 분리하고 실행 조건을 추가하는 방식으로 기존 코드를 수정한다.

그러나 특정 행동이 다른 코드와 복잡하게 연결되어 있다면 해당 부분만 분리하기 어려울 수 있다.

예를 들어 하나의 함수가 데이터 분석과 외부 전송을 동시에 수행한다면 전송 기능만 제거하는 과정에서 정상적인 분석 기능까지 영향을 받을 수 있다.

따라서 복잡한 코드 구조에 대해서는 더 정밀한 프로그램 분석과 리팩터링 기법이 필요하다.

### 6.3 테스트 시나리오의 완전성 문제

SkillScope는 실행 그래프를 바탕으로 다양한 사용자 요청을 생성한다.

그러나 모든 가능한 자연어 요청과 실행 경로를 완전히 탐색할 수는 없다.

특히 외부 서비스 인증이나 복잡한 환경 설정이 필요한 Skill에서는 실제 작업 조건을 재현하기 어려울 수 있다.

따라서 테스트되지 않은 사용자 요청에서 과도한 권한 사용이 발생할 가능성이 남아 있다.

### 6.4 실행 환경 자체의 접근 제어 문제

SkillScope는 현재 사용자 요청에 필요한 행동인지 판단하고 Skill의 지침과 실행 흐름을 수정하는 데 초점을 맞춘다.

하지만 이러한 접근만으로 운영체제 수준의 권한 격리나 외부 API 접근 통제를 완전히 대체할 수는 없다.

특히 악의적인 Skill이 제어 조건을 우회하거나 다른 경로로 민감한 기능을 실행하는 경우에는 추가적인 보호가 필요할 수 있다.

따라서 SkillScope를 실제 운영 환경에 적용할 때는 샌드박스, 파일 시스템 접근 제어, 네트워크 정책 등과 결합하는 것이 중요하다고 생각한다.

## 7. 내가 생각하는 후속 연구 방향

### 7.1 실시간 권한 검증으로 확장

가장 먼저 생각해 볼 수 있는 방향은 Skill 실행 전에 분석하는 것뿐 아니라 실행 도중에도 사용자 요청과 실제 행동을 비교하는 것이다.

SkillScope는 Skill을 사전에 분석하고 실행 조건을 수정하는 방식을 제안한다.

그러나 실제 에이전트는 실행 과정에서 새로운 도구를 선택하거나 예상하지 못한 작업을 수행할 수 있다.

따라서 각 도구 호출 직전에 해당 행동이 현재 사용자 요청에 필요한지 검증하는 Runtime Monitor를 추가할 수 있을 것이다.

이를 통해 정적인 분석에서 발견하지 못한 행동도 실시간으로 제한할 수 있을 것으로 생각한다.

### 7.2 다중 에이전트 환경으로 확장

SkillScope는 개별 Agent Skill의 행동을 중심으로 최소 권한 위반을 분석한다.

그러나 여러 에이전트가 협력하는 환경에서는 하나의 에이전트가 다른 에이전트에게 작업을 위임할 수 있다.

이 경우 처음 사용자에게 허가된 권한이 위임 과정에서 어떻게 전달되는지 확인할 필요가 있다.

예를 들어 문서 요약 권한만 부여받은 에이전트가 다른 에이전트에게 파일 수정이나 외부 전송을 요청한다면 권한 경계가 무너질 수 있다.

따라서 다중 에이전트 환경에서 권한 위임 관계와 실제 행동을 함께 검증하는 방식으로 확장할 수 있을 것이다.

### 7.3 사용자 의도와 실제 행동의 차이 검증

또 다른 방향은 자연어로 표현된 사용자 의도와 에이전트의 실제 실행 결과 사이의 차이를 분석하는 것이다.

사용자 요청은 항상 명확하게 작성되는 것은 아니다.

예를 들어 "필요한 자료를 모두 정리해 줘"라는 요청은 어떤 파일에 접근해도 되는지, 외부 서비스와 통신해도 되는지에 대한 구체적인 권한 범위를 정의하지 않는다.

따라서 모호한 요청에서 중요한 권한을 사용할 때는 추가 승인 절차를 거치도록 설계할 수 있다.

이와 함께 사용자 요청, 에이전트의 계획, 실제 도구 실행 기록을 비교하여 불필요한 행동이 발생하는 조건을 탐색할 수 있을 것이다.

## 8. 결론 및 느낀 점

이 논문을 읽으며 가장 인상적이었던 점은 Agent Skill의 보안을 악의적인 코드의 존재 여부가 아니라, 실제 사용자 요청에 필요한 행동인지 여부로 판단한다는 것이다.

기존의 소프트웨어 보안 분석에서는 위험한 함수나 의심스러운 코드 패턴을 탐지하는 방식이 많이 사용된다.

그러나 Agent Skill에서는 특정 행동이 위험하다는 사실만으로 보안 위반이라고 판단하기 어렵다.

예를 들어 외부 서버로 데이터를 전송하는 기능은 정보 유출에 악용될 수 있지만, 사용자가 명시적으로 전송을 요청한 경우에는 정상적인 기능이 될 수도 있다.

따라서 SkillScope가 Authorization과 Necessity를 구분하여 행동을 검증한다는 점이 흥미로웠다.

특히 Replay Execution을 활용한 검증 방식이 인상적이었다.

단순히 LLM에 특정 행동이 필요한지 질문하는 것이 아니라, 해당 행동을 제거한 상태에서 실제 작업을 다시 실행하고 결과를 비교한다는 점에서 판단 근거를 확보하려는 접근이라고 생각한다.

또한 위험한 기능을 무조건 삭제하는 것이 아니라 조건부로 실행하도록 수정한 점도 의미가 있다.

보안 기능이 지나치게 엄격하면 사용자가 원래 수행하려던 작업까지 방해할 수 있기 때문이다.

이러한 관점에서 SkillScope는 보안성과 기능성 사이의 균형을 고려한 연구라고 볼 수 있다.

다만 이 연구는 사용자 요청의 의미를 LLM이 올바르게 해석한다는 가정에 영향을 받는다. 자연어 요청이 모호하거나 에이전트의 행동이 복잡한 경우에는 최소 권한 위반 여부를 일관되게 판단하기 어려울 수 있다.

또한 Skill을 수정하는 방식만으로 실제 시스템 권한을 완전히 제한할 수는 없으므로 보다 강력한 실행 환경의 접근 제어와 결합할 필요가 있다고 생각한다.

결과적으로 SkillScope는 **Agent Skill의 자연어 지침과 실행 코드를 통합적으로 분석하고, 사용자 요청에 대한 행동의 필요성과 권한을 검증하여 과도한 권한 사용을 제한하는 프레임워크**라고 정리할 수 있다.

이번 논문을 통해 에이전트 보안에서는 취약점을 발견하는 것뿐 아니라, 사용자가 의도한 작업 범위 안에서만 에이전트가 행동하도록 보장하는 것이 중요하다는 점을 배울 수 있었다.
