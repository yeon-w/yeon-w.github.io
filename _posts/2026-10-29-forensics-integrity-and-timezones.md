포렌식 실습에서 분석 결과만큼 중요한 것은 **어떤 파일을, 어떤 기준 시각으로 해석했는지**다. 이 글은 특정 사건의 분석 기록이 아니라, 허가된 연습용 이미지나 공개 샘플을 다룰 때 쓸 기록 틀이다.

## 시작할 때 남길 정보

| 항목 | 기록할 내용 |
| --- | --- |
| 출처 | 공개 샘플의 공식 링크 또는 실습 제공 경로 |
| 원본 | 파일명, 크기, 제공된 해시값이 있는지 |
| 작업본 | 원본과 분리한 분석용 사본의 위치 |
| 도구 | 해시·분석 도구의 이름과 버전 |
| 시각 | 시스템 시간대와 아티팩트가 표시한 시간대 |

macOS에서는 연습용 파일에 대해 `shasum -a 256 sample.img`로 SHA-256 값을 구할 수 있다. 분석 전후에 같은 파일의 해시가 같다면 **그 사이에 파일 내용이 바뀌지 않았다는 근거**가 된다. 해시 일치만으로 파일의 출처나 진위를 증명할 수는 없다. 원본은 보존하고 사본에서 분석한다.

## 타임스탬프를 해석할 때

`2026-10-29 09:00 KST`와 `2026-10-29 00:00 UTC`는 같은 순간이다. 화면에 표시된 시각을 옮겨 적을 때는 `KST` 또는 `UTC`처럼 시간대까지 적는다. 파일 시스템, 애플리케이션, 로그가 각각 다른 기준을 사용할 수 있고, 일부 지역은 일광 절약 시간도 적용한다.

하나의 시간이 곧바로 사용자의 행동을 뜻하는지도 확인해야 한다. 생성·수정·접근 시각의 의미는 파일 시스템과 수집 방식에 따라 달라질 수 있다. 보고서에는 **원본 표시값 → 변환 기준 → 해석**을 분리해 적는다.

```text
아티팩트: [종류와 경로]
원본 시각: [값과 알려진 시간대]
변환 시각: [UTC 또는 KST]
해석 근거: [도구·문서·교차 검증 자료]
남은 불확실성: [시간대 미상, 시계 오차 등]
```

CTF 풀이를 공개할 때는 대회 규칙과 문제 공개 시점을 먼저 확인하고, 실제 사건 자료나 개인정보를 예시로 올리지 않는다.
