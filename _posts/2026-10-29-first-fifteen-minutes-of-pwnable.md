네이버 블로그에 남긴 워게임 라이트업 18편을 다시 읽었다. 이 중 13편은 개별 문제의 풀이·분석이고, 5편은 주차별로 글을 모은 목차다. 이번 글에서는 풀이 코드를 모두 옮기기보다, 어디를 먼저 확인했고 어떤 원리로 접근했는지를 분야별로 정리했다.

## 웹 해킹: 입력이 처리되는 경로 살펴보기

- 쿠키에서는 guest로 로그인한 뒤 브라우저 개발자 도구에서 쿠키값을 admin으로 바꿨다. 서버가 클라이언트의 값을 어떻게 신뢰하는지 확인한 문제였다.

- simple-web-request는 각 단계의 입력 조건과 숨겨진 check 값을 확인하며 요청을 진행했다.

- file-download-1은 app.py와 메모 링크를 살펴본 뒤 ../flag.py 경로로 접근했다. 파일 경로를 다루는 기능에서 경로 탐색이 왜 중요한지 보여줬다.

- xss-2는 URL의 param 값이 innerHTML로 페이지에 삽입되는 지점을 찾았다. 이벤트 핸들러를 이용해 봇의 쿠키가 메모에 남는 과정을 확인했다.

- simple_sqli는 로그인 화면만 보고 추측하지 않고 app.py의 인증 조건을 읽은 뒤 관리자 로그인 경로를 확인했다. 원문에는 SQL 인젝션 페이로드를 사용했다는 기록이 없어, 여기서도 그렇게 설명하지 않았다.

## 암호학과 Misc: 변환 규칙 거꾸로 따라가기

- ROT128은 파일 바이트에 적용된 +128 mod 256 변환을 파악하고 이미지를 복원했다.

- 64se64는 HTML의 숨겨진 입력값에서 Base64 문자열을 찾아 디코딩하고, 이어지는 Python·ASCII 표현을 해석했다.

- textbook-DH는 공개키 검증이 특정 값만 막는다는 점에 주목했다. 공개키로 1을 넣어 예측 가능한 공유키를 만들고 암호문을 복호화했다.

- 40 birthday는 SHA-256 전체가 아닌 5바이트만 비교한다는 조건을 확인했다. 서로 다른 두 입력의 해당 부분이 같아지는 충돌을 찾아 문제를 해결했다.

## 시스템 해킹과 리버싱: 실행 흐름 역산 하기

- rop에서는 카나리와 NX가 있는 바이너리를 분석했다. 출력 과정에서 카나리를 확인하고, libc 주소 계산과 GOT 변경을 포함한 ROP 흐름을 구성해 쉘을 얻었다고 기록했다.

- shell_basic은 입력 바이트를 실행 가능한 메모리에 올리는 코드를 분석하고, 파일을 열고 읽어 출력하는 ORW 셸코드의 흐름을 정리했다.

- simple-operation은 XOR, 16진수 변환, 문자열 역순 비교 조건을 거꾸로 따라가며 필요한 입력값을 계산했다.

- basic_exploitation_001은 길이 제한이 없는 gets()와 128바이트 버퍼를 확인했다. 반환 주소까지의 거리 136바이트를 계산하고 실행 흐름을 read_flag()로 바꿔 정답을 확인했다.

## 주차별 기록

풀이를 모아 둔 글도 그대로 남겨 두었다. 1주차는 웹 해킹 3문제, 2주차는 ROT128과 64se64, 3주차는 shell_basic과 simple-operation을 묶었다. 4주차는 xss-2와 simple_sqli, 5주차는 textbook-DH와 40 birthday로 이어진다.

문제마다 다루는 대상은 달랐지만, 풀이의 출발점은 비슷했다. 제공된 코드와 실제 입력 경로를 먼저 확인하고, 검증 조건을 작은 단계로 나눈 뒤 결과를 관찰하는 것이다. 앞으로도 성공 화면뿐 아니라 중간에 세운 가설과 확인 방법을 함께 남겨, 다시 읽었을 때 풀이 과정을 재현할 수 있는 라이트업을 쓰고 싶다.
