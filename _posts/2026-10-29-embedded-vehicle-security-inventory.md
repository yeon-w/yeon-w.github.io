임베디드·차량 보안은 소프트웨어뿐 아니라 하드웨어 버전, 물리적 연결, 안전 기능이 얽혀 있다. 그래서 실습 전에 **시스템 지도와 안전 경계**를 먼저 적어 두는 것이 좋다. 아래 내용은 특정 차량을 분석했다는 기록이 아닌, 승인된 실습 장비나 공개 문서를 읽을 때 쓸 틀이다.

## 시스템 인벤토리

| 항목 | 확인할 질문 |
| --- | --- |
| 구성요소 | 어떤 보드·모듈·센서·제어기가 있는가? |
| 버전 | 하드웨어 개정, 펌웨어, 부트로더 버전은 무엇인가? |
| 연결 | 외부 입력과 내부 통신의 경계는 어디인가? |
| 업데이트 | 공식 업데이트 경로와 검증 방법은 무엇인가? |
| 관찰 수단 | 안전하게 확인 가능한 로그·문서는 무엇인가? |
| 권한 | 장비 소유자와 실습 허가 범위는 어디까지인가? |

같은 제품명이라도 버전이 다르면 동작과 보안 속성이 달라질 수 있다. 문서에서 확인한 사실과 실제 장비에서 관찰한 사실을 따로 표시한다.

## 안전 경계를 먼저 정하기

- 실제 운행 중인 차량이나 공용 장비를 학습 대상으로 삼지 않는다.
- 제동·조향·동력 등 안전 기능에 영향을 주는 실험은 수행하지 않는다.
- 승인된 실습 장비의 전원, 연결, 복구 절차를 담당자와 확인한다.
- 수집한 로그에 위치 정보나 개인 정보가 있는지 확인한 뒤 공개 범위를 정한다.

## 다음 단계의 기록 방식

```text
대상: [장비/문서와 버전]
출처: [공식 자료 또는 승인된 실습 환경]
확인한 사실: [문서 내용 또는 직접 관찰]
추정한 구조: [가설이라고 표시]
안전 제한: [시험하지 않을 기능과 조건]
다음 질문: [읽을 문서 또는 비침습적 확인 항목]
```

이 지도는 이후 연구나 개발의 출발점이다. 특히 안전과 관련된 시스템에서는 "확인하지 못했다"는 표기도 중요한 정보다.
