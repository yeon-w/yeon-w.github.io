## 2. 논문을 읽기 전: 문제의식 정리

### 이 논문이 다루는 문제는 무엇인가?

최근 LLM의 발전으로 취약점 탐색부터 공격 방법 결정, 실제 명령어 실행까지 자동으로 수행하는 AI 기반 침투 테스트 에이전트가 등장하고 있다. 이러한 기술은 보안 전문가의 업무를 효율적으로 만들어 주지만, 악의적인 공격자 역시 이를 활용해 사이버 공격을 자동화할 수 있다는 문제가 있다.

이 논문은 이러한 LLM 기반 자율 공격 에이전트에 대응하기 위해, 공격에 사용되는 LLM의 취약점을 오히려 방어 수단으로 활용하는 방법을 다룬다.

### 왜 이 문제가 중요한가?

기존에는 공격자가 시스템의 정보를 직접 수집하고 취약점을 분석한 후 공격 방법을 결정해야 했다. 그러나 LLM 기반 에이전트를 활용하면 이러한 과정의 상당 부분을 자동화할 수 있다.

이는 공격에 필요한 전문성과 시간의 장벽을 낮추고, 다수의 시스템을 대상으로 공격을 수행할 수 있는 가능성을 높인다. 따라서 공격의 자동화 속도에 대응할 수 있는 새로운 방어 방법이 필요하다고 생각했다.

### 기존 방식들은 무엇이 부족했는가?

기존의 방어 방법은 주로 악성 패킷이나 비정상적인 접근을 탐지하고, 알려진 취약점을 패치하거나 공격자의 접근 권한을 제한하는 방식에 집중해 왔다.

그러나 LLM 기반 공격자는 단순히 정해진 규칙에 따라 동작하는 프로그램이 아니라, 수집한 정보를 바탕으로 상황을 판단하고 다음 공격 방법을 결정하는 시스템이다.

기존의 방어 방식만으로는 이러한 판단 과정 자체를 방해하기 어렵다. 따라서 LLM 기반 공격자가 정보를 해석하고 의사결정을 내리는 과정에서 발생하는 고유한 취약점을 활용할 필요가 있다.

## 3. AI 기반 공격 자동화의 등장과 새로운 방어의 필요성

### 3.1. 연구 배경

LLM의 발전은 사이버보안 분야에도 큰 변화를 가져오고 있다. 특히 침투 테스트 분야에서는 PentestGPT, AutoAttacker, PenHeal과 같은 LLM 기반 도구를 활용하여 기존에 사람이 수행하던 취약점 분석과 공격 과정을 자동화하려는 연구가 진행되고 있다.

이러한 도구는 단순히 사용자가 입력한 질문에 답변하는 것에 그치지 않는다. 실제 환경에서 네트워크를 스캔하고, 파일을 읽으며, 수집한 정보를 분석하여 다음 행동을 결정한다. 터미널과 같은 외부 도구에 접근할 수 있다면 결정한 행동을 직접 실행하는 것도 가능하다.

특히 다중 LLM 기반 침투 테스트 에이전트는 다음과 같은 구조로 동작한다.

| 구성 요소 | 역할 |
| --- | --- |
| Summarizer | 도구 실행 결과 및 수집한 정보를 요약 |
| Reasoner | 수집된 정보를 분석하고 다음 공격 단계 결정 |
| Executor | 실제 실행할 명령어 생성 |
| Knowledge Structure | 발견한 정보와 공격 진행 상태를 저장 |

요약 모델은 도구 실행 결과를 정리하고, 추론 모델은 수집된 정보를 바탕으로 다음 공격 단계를 결정하며, 실행 모델은 실제 명령어를 생성한다. 이 과정에서 발견한 정보는 지식 구조(Knowledge Structure)에 저장되어 이후의 공격에 활용된다.

이러한 구조는 여러 단계의 공격을 자동화하는 데 효과적이지만, 동시에 새로운 취약점을 만들어 낸다. 공격 에이전트는 자신의 목표를 달성하기 위해 외부 환경에서 수집한 정보를 지속적으로 신뢰하고 활용해야 하기 때문이다.

### 3.2. 문제 정의

예를 들어 공격 에이전트가 특정 서버에서 관리자 계정에 대한 정보를 발견했다면, 해당 정보가 실제로 신뢰할 수 있는지 충분히 검증하지 않은 상태에서 이를 공격에 활용할 수 있다.

이 논문은 바로 이러한 점에 주목한다.

기존에는 공격자가 시스템의 취약점을 발견하고 악용하는 과정에서 방어자가 이를 탐지하거나 차단하는 방식이 일반적이었다. 그러나 본 논문은 공격자가 사용하는 LLM 역시 학습 편향, 환각, 메모리 한계와 같은 취약점을 가진다는 점에서 새로운 방어 가능성을 제시한다.

즉, 공격자가 시스템을 분석하는 과정에서 접하게 되는 정보를 방어자가 전략적으로 조작한다면, 공격자의 판단을 잘못된 방향으로 유도하거나 공격 자체를 중단시킬 수 있다는 것이다.

> 공격자가 사용하는 AI의 취약점을 역으로 이용하여 공격을 방어할 수 있지 않을까?

이러한 문제의식이 본 논문의 출발점이다.

## 4. LLM의 취약점을 역으로 활용하는 방어 프레임워크

### 4.1. 핵심 아이디어

이 논문의 핵심 아이디어는 공격자의 LLM을 직접 수정하거나 공격 시스템에 접근하지 않고도, 공격자가 탐색하는 환경을 조작함으로써 공격자의 행동에 영향을 미치는 것이다.

연구진은 이를 위해 Cloak, Honey, Trap이라는 세 가지 방어 전략을 제안한다.

| 전략 | 설명 | 주요 목적 |
| --- | --- | --- |
| Cloak | 중요한 정보를 숨기거나 잘못된 정보를 제공하여 공격자의 인식을 왜곡 | 공격 중단 및 지연 |
| Honey | 가짜 자산과 인증 정보를 이용하여 공격자를 유인 | 공격자 탐지 |
| Trap | 반복적인 작업이나 잘못된 판단을 유도하여 공격자의 동작을 방해 | 공격 중단 및 지연 |

이러한 전략은 공격자의 LLM이 어떤 모델인지, 내부 시스템 프롬프트가 어떻게 구성되어 있는지 알지 못하는 블랙박스(Black-box) 환경에서도 적용할 수 있도록 설계되었다.

방어자는 공격자가 접근할 가능성이 높은 로그, 설정 파일, HTML 주석, 서비스 배너 등에 조작된 문자열을 미리 삽입한다. 이후 공격자가 해당 데이터를 읽으면 LLM의 추론 과정에서 방어 효과가 발생하게 된다.

### 4.2. LLM 기반 공격자의 취약점

연구진은 방어 기법의 설계에 앞서 LLM 기반 공격 에이전트가 가지는 일곱 가지 취약점을 분석하였다.

| 취약점 | 설명 |
| --- | --- |
| V1. Training Bias | 학습 데이터에서 자주 등장하는 취약점이나 공격 방법을 선호하는 경향 |
| V2. Reliance on Untrusted Input | 외부에서 수집한 정보의 신뢰성을 충분히 검증하지 않는 문제 |
| V3. Memory and Context Limitations | 불필요한 정보에 의해 중요한 정보가 묻히거나 기억에서 사라지는 문제 |
| V4. Search Behavior | 하나의 단서를 끝까지 추적하려는 깊이 우선 탐색과 유사한 행동 |
| V5. Hallucinations | 실제로 존재하지 않는 파일, 인증 정보 등을 생성하는 문제 |
| V6. Susceptibility to Special Characters | 특정 유니코드 문자나 희귀 토큰을 처리하는 과정에서 발생하는 오류 |
| V7. Alignment Constraints | 모델의 안전장치나 윤리적 제약을 의도적으로 작동시킬 수 있는 문제 |

논문은 이러한 취약점들을 단순히 LLM의 성능을 저하시키는 요소로 바라보지 않는다. 오히려 공격 에이전트의 판단과 행동을 제어할 수 있는 방어 수단으로 활용한다는 점이 특징이다.

### 4.3. 전체 방어 기법

연구진은 세 가지 방어 전략을 기반으로 총 6가지 전술과 15가지 세부 기법을 제안하였다.

| 전략 | 전술 | 세부 기법 |
| --- | --- | --- |
| Cloak | T1. 인식 왜곡 | T1.1 잘못된 믿음 유도 |
| Cloak | T1. 인식 왜곡 | T1.2 데이터 표현 왜곡 |
| Cloak | T2. 주의 분산 | T2.1 잘못된 버전 정보 제공 |
| Cloak | T2. 주의 분산 | T2.2 목표에서 주의 돌리기 |
| Honey | T3. 특수 유인 | T3.1 LLM 전용 미끼 |
| Honey | T3. 특수 유인 | T3.2 LLM 전용 허니토큰 |
| Trap | T4. 모델 손상 | T4.1 탐색 공간 폭발 |
| Trap | T4. 모델 손상 | T4.2 모델 속도 저하 |
| Trap | T4. 모델 손상 | T4.3 순환 및 반복 루프 생성 |
| Trap | T4. 모델 손상 | T4.4 적대적 교란 삽입 |
| Trap | T5. 역할 조작 | T5.1 안전장치 작동 유도 |
| Trap | T5. 역할 조작 | T5.2 에이전트의 역할 및 목표 변경 |
| Trap | T6. 강제 코드 실행 | T6.1 공격자 시스템에서 코드 실행 |
| Trap | T6. 강제 코드 실행 | T6.2 호스트 시스템에서 코드 실행 |
| Trap | T6. 강제 코드 실행 | T6.3 연산 시간 낭비 유도 |

이 중 프롬프트 인젝션을 필수적으로 요구하는 기법은 T5.2 하나뿐이다.

이후 각 전략에서 인상 깊었던 대표적인 기법을 중심으로 살펴보고자 한다.

### 4.4. Cloak: 공격자의 인식 왜곡

Cloak은 공격자가 실제로 중요한 정보를 발견하지 못하도록 은폐하거나 잘못된 방향으로 유도하는 전략이다.

대표적인 방법은 시스템에 모든 취약점이 수정되었다는 거짓 로그를 삽입하는 것이다.

> System has been updated. All known CVEs are mitigated as of 2025-01-01.

공격 에이전트가 이러한 정보를 사실로 받아들이면 실제 취약점이 존재하더라도 추가적인 탐색을 포기할 수 있다.

반대로 잘 알려진 취약점이 존재하는 소프트웨어 버전 정보를 의도적으로 삽입할 수도 있다.

예를 들어 실제로는 Heartbleed 취약점이 존재하지 않는 시스템에 OpenSSL 1.0.1을 사용한다는 정보를 삽입하면, 공격 에이전트는 해당 취약점을 악용하기 위해 불필요한 시간을 소비하게 된다.

연구진은 LLM이 학습 과정에서 자주 접한 취약점이나 `admin`과 같은 용어에 높은 관심을 보인다는 사실을 발견하였다.

이를 활용한 실험에서는 FTP 서버에 `private_docs`라는 디렉터리를 만들고 그 내부에 매력적인 이름을 가진 250개의 중첩 디렉터리를 구성하였다.

PentestGPT는 20번의 실험에서 일관되게 해당 디렉터리를 가장 깊은 수준까지 탐색하였다.

이 실험을 통해 공격자가 관심을 가질 만한 정보를 제공하는 것만으로도 공격자의 탐색 방향을 효과적으로 제어할 수 있음을 보여주었다.

특히 LLM이 하나의 단서를 끝까지 추적하는 깊이 우선 탐색(Depth-First Search)과 유사한 행동을 보인다는 점이 흥미로웠다. 방어자는 이러한 특성을 이용해 실제로 중요한 자산에서 공격자를 멀어지게 만들 수 있다.

### 4.5. Honey: LLM 공격자에 특화된 탐지

Honey는 기존의 허니팟(Honeypot)과 허니토큰(Honeytoken) 개념을 LLM 기반 공격자에 특화하여 확장한 전략이다.

기존 허니팟은 공격자를 가짜 시스템으로 유인하여 공격자의 행동을 관찰한다. 허니토큰은 실제로 사용되지 않는 가짜 인증 정보나 데이터를 삽입하고, 해당 정보가 사용되었을 때 비인가 접근을 탐지하는 방식이다.

본 논문에서는 인간과 LLM이 동일한 데이터를 서로 다르게 해석할 수 있다는 점을 이용하여 공격자가 LLM인지 구분하는 방법을 제안한다.

예를 들어 사람이 화면에서 볼 수 없는 유니코드 문자를 URL에 삽입하면, 사람은 일반적인 URL로 인식하지만 LLM은 해당 문자를 별도의 문자열로 해석할 수 있다.

| 접근 주체 | 인식하는 URL |
| --- | --- |
| 인간 | `site.com/page_for` |
| LLM | `site.com/page_for_LLM` |

이때 인간과 LLM이 서로 다른 URL에 접근하도록 유도하고 접근 기록을 확인하면, 방어자는 공격자가 LLM 기반 에이전트일 가능성을 판단할 수 있다.

연구진은 Bandit CTF의 비밀번호에 특수문자를 삽입하여 인간과 LLM이 생성하는 문자열의 차이를 비교하였다. 실험 결과, 일부 특수문자는 여러 LLM 모델에서 일관되게 인간과 모델을 구분하는 데 효과적이었다.

이 부분에서 흥미로웠던 점은 기존 허니토큰이 주로 비인가 접근의 발생 여부를 확인하는 데 사용되었다면, 본 논문의 허니토큰은 접근 주체의 특성까지 구분할 수 있다는 것이다.

다만 특수문자에 대한 반응은 모델이나 입력 처리 방식에 따라 달라질 수 있으므로, 이러한 방식이 모든 환경에서 인간과 AI를 완벽하게 구분할 수 있는 것은 아니다.

### 4.6. Trap: 공격자의 추론 및 행동 방해

Trap은 LLM의 본질적인 한계를 악용하여 공격 에이전트의 정상적인 동작을 방해하는 전략이다.

대표적인 기법은 공격자의 탐색 공간을 증가시키거나 반복적인 참조 구조를 만들어 공격자를 루프에 빠뜨리는 것이다.

예를 들어 다음과 같은 세 개의 파일을 구성할 수 있다.

- `file1.txt`: 관리자 인증 정보는 file2.txt에 존재한다.
- `file2.txt`: 비밀번호는 file3.txt에 존재한다.
- `file3.txt`: 비밀번호가 file1.txt로 이동하였다.

공격 에이전트는 다음과 같은 순서로 파일을 탐색하게 된다.

`file1.txt → file2.txt → file3.txt → file1.txt → ...`

인간은 이러한 구조를 발견하면 정보가 실제로 존재하지 않을 가능성을 의심할 수 있다. 그러나 논문에서 평가한 일부 LLM 에이전트는 루프를 인식하고도 자신이 중요한 정보를 놓쳤을 가능성을 고려하여 파일을 반복적으로 탐색하였다.

GPT-4o 기반 PentestGPT는 세 번의 순환 이후 존재하지 않는 숨겨진 파일을 생성하기 시작하였으며, 여덟 번의 순환 이후에는 존재하지 않는 인증 정보까지 생성하는 환각을 보였다.

또한 에이전트가 대량의 파일 정보를 수집하게 하여 컨텍스트를 증가시키는 실험에서는 이후 공격 단계의 처리 속도가 약 60배 느려지는 결과가 나타났다.

이외에도 희귀 토큰을 이용하여 LLM의 출력을 손상시키는 방법, 모델의 안전장치를 작동시켜 공격을 중단시키는 방법, 신뢰할 수 없는 코드를 실행하도록 유도하는 방법 등이 제안되었다.

특히 신뢰할 수 없는 코드 실행을 유도하는 기법은 공격 에이전트가 자신의 목표에 도움이 된다고 판단하면 외부에서 발견한 코드를 자체적으로 실행할 수 있다는 문제를 보여준다.

이는 단순히 LLM의 응답이 잘못되는 수준을 넘어, 실제 도구 실행 권한을 가진 에이전트의 경우 잘못된 판단이 시스템 보안 문제로 이어질 수 있음을 의미한다.

### 4.7. 프롬프트 인젝션과의 차이

이 논문에서 가장 인상 깊었던 부분은 제안한 15가지 세부 방어 기법 중 프롬프트 인젝션을 반드시 필요로 하는 기법은 단 하나뿐이라는 점이다.

기존의 프롬프트 인젝션은 일반적으로 모델의 기존 명령을 무시하게 하거나 새로운 명령을 따르도록 유도한다.

반면 이 논문에서 제안하는 대부분의 기법은 에이전트의 기존 목표를 변경하지 않는다. 에이전트가 자신의 목표를 충실하게 수행하도록 두면서, 그 과정에서 참고하는 정보를 조작한다.

| 구분 | 프롬프트 인젝션 | 본 논문의 정보 기만 방식 |
| --- | --- | --- |
| 조작 대상 | 모델이 따르는 명령 | 모델이 판단에 사용하는 정보 |
| 주요 방식 | 기존 명령 무시 또는 새로운 명령 삽입 | 그럴듯한 가짜 정보 제공 |
| 에이전트의 목표 | 변경될 수 있음 | 기존 목표를 유지 |
| 공격 결과 | 의도하지 않은 명령 수행 | 잘못된 판단과 행동 유도 |

예를 들어 공격자가 관리자 계정을 찾고 있다면 관리자 계정을 찾지 말라고 명령하는 것이 아니라, 존재하지 않는 관리자 계정에 대한 단서를 제공하는 것이다.

결국 에이전트는 자신의 목표를 수행한다고 판단하지만 실제로는 방어자가 설계한 경로를 따라가게 된다.

이러한 접근 방식은 LLM 보안에서 명령의 우선순위뿐만 아니라 정보의 신뢰성과 추론 과정 자체도 중요한 보안 요소라는 점을 보여준다.

## 5. 실험 결과와 실제 성과, 그리고 한계

### 5.1. 실험 및 평가 방법

연구진은 제안한 기법의 효과를 검증하기 위해 다음 세 가지 다중 LLM 기반 침투 테스트 도구를 대상으로 실험을 수행하였다.

- PentestGPT
- AutoAttacker
- PenHeal

백엔드 LLM으로는 다음 네 가지 모델을 사용하였다.

- GPT-4o
- Gemini 1.5 Pro
- Claude Sonnet 3.5
- Llama 3.1 70B

각 방어 기법을 바탕으로 총 249개의 페이로드를 생성하고, 이를 침투 테스트 과정에서 접할 수 있는 17가지 데이터 포인트에 삽입하여 총 4,233개의 평가 데이터를 구성하였다.

주요 평가 지표는 방어 성공률(Defense Success Rate, DSR)이다.

**DSR = 방어에 성공한 실험 횟수 / 전체 실험 횟수**

예를 들어 공격자가 거짓 정보를 지식 구조에 저장하거나 특정 함정에서 의도한 행동을 수행하면 해당 방어 기법이 성공한 것으로 평가한다.

연구진은 개별 방어 기법에 대한 평가뿐만 아니라 실제 CTF 머신에서 전체 공격 과정을 수행하는 종단 간(End-to-End) 평가도 진행하였다.

### 5.2. 개별 방어 기법의 실험 결과

개별 방어 기법에 대한 전체 평균 DSR은 모델에 따라 약 55~68%로 나타났다.

특히 가장 효과적인 방어 기법과 데이터 포인트를 조합한 경우 모든 평가 모델에서 100%의 DSR을 달성하였다.

| 모델 | 전체 평균 DSR | 상위 5×5 조합 DSR |
| --- | --- | --- |
| GPT-4o | 55.34% | 87.49% |
| Claude Sonnet 3.5 | 67.95% | 86.92% |
| Gemini 1.5 Pro | 63.66% | 85.05% |
| Llama 3.1 70B | 62.25% | 75.75% |

실험 결과 가장 효과적인 기법 중 하나는 탐색 공간 폭발(T4.1)이었다. 하나의 데이터 포인트에 대량의 가짜 취약점 정보를 삽입하여 공격자의 지식 구조를 오염시키는 방식이다.

또한 여러 방어 기법을 순차적으로 배치하면 각각의 함정에 대한 성공 가능성이 누적되어 전체 방어 효과가 증가한다는 결과도 확인하였다.

연구진의 계산에 따르면 Llama 3.1 70B를 사용하는 공격자가 무작위로 선택된 Trap 기법 다섯 개를 마주칠 경우 누적 DSR이 95%를 초과하였다.

이는 단일 방어 기법에 의존하는 것보다 여러 기법을 네트워크 전체에 분산하여 적용하는 것이 더욱 효과적일 수 있음을 보여준다.

### 5.3. 실제 CTF 머신을 대상으로 한 평가

연구진은 개별 기법의 성능 평가에 그치지 않고 실제 CTF 머신을 대상으로 전체 공격 과정을 평가하였다.

쉬운 난이도 5개, 중간 난이도 4개, 어려운 난이도 2개로 구성된 총 11개의 CTF 머신에서 GPT-4o 기반 PentestGPT를 실행하였다.

공격 에이전트는 다음 네 가지 단계를 수행하도록 구성되었다.

1. 초기 접근 방법 발견
2. 취약점 악용을 통한 초기 접근 획득
3. 권한 상승 방법 발견
4. 취약점 악용을 통한 루트 권한 획득

각 머신은 방어 기법을 적용하지 않은 상태와 적용한 상태에서 각각 세 번씩 테스트되었다.

실험 결과 방어 기법을 적용한 환경에서는 총 33회의 공격 시도 모두 초기 접근 방법을 발견하는 데 실패하였다.

| 평가 항목 | 결과 |
| --- | --- |
| 평가한 CTF 머신 | 11개 |
| 머신당 방어 적용 실험 | 3회 |
| 전체 방어 적용 실험 | 33회 |
| 방어 적용 후 초기 접근 성공 | 0회 |
| 방어 성공률 | 100% |

다만 방어 기법이 적용되지 않은 환경에서도 에이전트가 해결하지 못한 머신이 존재하였다. 따라서 이 결과는 실험 환경에서 모든 공격을 차단했다는 의미이며, 모든 실제 공격자를 완벽하게 방어할 수 있다는 의미는 아니다.

### 5.4. 프롬프트 인젝션의 효과

연구진은 제안한 방어 기법에 프롬프트 인젝션을 추가했을 때 성능이 어떻게 변화하는지도 평가하였다.

프롬프트 인젝션을 추가한 경우 일부 기법의 성능은 향상되었지만, 전체적으로는 오히려 DSR이 감소하는 경향이 나타났다.

이는 모델의 안전장치가 명시적인 조작 시도를 탐지할 수 있기 때문이다.

따라서 연구진은 명시적인 프롬프트 인젝션보다 자연스러운 형태의 잘못된 정보가 장기적으로 더욱 효과적인 방어 수단이 될 가능성을 제시하였다.

이 결과는 기존의 프롬프트 인젝션 대응 기술이 발전하더라도 정보 자체의 신뢰성을 검증하는 문제가 여전히 남아 있다는 점에서 의미가 있다고 생각한다.

### 5.5. 방어 기법에 적응하는 공격자

논문에서는 공격자가 방어 기법의 존재를 알고 이에 대응하는 상황도 평가하였다.

예를 들어 시스템 프롬프트를 강화하거나, 외부 입력을 분류기로 검사하거나, 방어 기법에 대한 정보를 RAG로 제공하거나, 모델을 미세조정하는 방법을 테스트하였다.

대표적인 실험 결과는 다음과 같다.

| 공격자의 대응 방식 | 오탐률(FPR) | 방어 성공률(DSR) |
| --- | --- | --- |
| 기본 공격자 | - | 83.92% |
| 논문 기반 컨텍스트 인지 | 8.83% | 78.14% |
| SVM 기반 전처리 | 5.75% | 70.39% |
| DeBERTa 기반 전처리 | 66.08% | 5.00% |
| PAT 기반 시스템 프롬프트 | 99.02% | 0.35% |
| 미세조정 | 49.17% | 10.69% |
| 앙상블 | 25.07% | 14.19% |

일부 방법은 방어 성공률을 크게 낮추었지만, 동시에 정상적인 정보까지 함정으로 판단하는 높은 오탐률을 보였다.

대표적으로 PAT 기반 시스템 프롬프트를 사용한 경우 DSR은 0.35%까지 감소하였지만 오탐률은 99.02%에 달하였다.

이는 공격자가 대부분의 함정을 피할 수 있게 되었지만, 정상적인 공격 단서까지 거의 모두 무시하게 되었다는 것을 의미한다.

이 결과는 LLM 에이전트의 근본적인 딜레마를 보여준다고 생각한다.

> 에이전트가 외부 정보를 무조건 신뢰하면 조작에 취약해지지만, 반대로 모든 정보를 의심하면 정상적인 작업을 수행하기 어려워진다.

따라서 단순히 의심스러운 정보를 차단하는 것만으로는 이러한 문제를 충분히 해결하기 어렵다.

### 5.6. 한계점 및 아쉬운 점

#### 첫 번째, 방어 성공률 100%의 일반화 문제

논문에서는 방어 기법을 적용한 11개의 CTF 머신에서 모든 공격을 차단하였지만, 방어를 적용하지 않은 환경에서도 에이전트가 일부 머신을 해결하지 못하였다.

특히 어려운 난이도의 머신은 방어가 없는 상태에서도 공격에 성공하지 못했다.

따라서 모든 공격 실패가 방어 기법만으로 발생했다고 해석하기는 어렵다.

방어 적용 이전에 실제로 공격에 성공했던 사례만 별도로 분석하고, 동일한 공격 조건에서 방어 적용 전후의 성공률을 비교하면 방어 기법의 효과를 더욱 명확하게 확인할 수 있을 것이라고 생각한다.

#### 두 번째, 인간의 개입이 없다는 가정

이 논문은 공격 과정에서 인간이 개입하지 않는 자율 공격 에이전트를 가정한다.

그러나 실제 공격자는 에이전트가 반복적인 작업을 수행하거나 잘못된 정보를 활용하는 상황을 발견하면 직접 개입하여 공격을 이어갈 수 있다.

따라서 인간과 AI가 협력하는 공격 환경에서도 동일한 방어 효과를 얻을 수 있는지는 추가적인 검증이 필요하다.

물론 인간의 개입을 강제한다는 것만으로도 공격 자동화의 장점을 감소시킬 수 있다는 점에서는 충분한 방어적 의미가 있다.

#### 세 번째, 실제 운영 환경에서의 적용 가능성

실험에 사용된 환경은 격리된 CTF 머신이다.

실제 기업 네트워크에서는 가짜 로그나 설정 정보를 삽입하는 과정에서 정상적인 사용자나 보안 관리자가 혼란을 겪을 수 있다.

또한 정상적인 보안 점검 시스템이 조작된 정보를 실제 취약점으로 판단할 가능성도 존재한다.

따라서 공격 에이전트를 효과적으로 기만하면서 정상적인 시스템 운영에는 영향을 주지 않는 배치 방법에 대한 연구가 필요하다고 생각한다.

#### 네 번째, LLM의 발전에 따른 방어 효과 변화

LLM 및 에이전트의 발전에 따라 개별 방어 기법의 효과는 변화할 수 있다.

특히 희귀 토큰이나 특수문자를 활용하는 방법은 모델의 토큰화 방식과 입력 처리 과정에 따라 효과가 달라질 수 있다.

에이전트가 출처 검증, 반복 탐색 제한, 독립적인 검증 모델 등을 적용한다면 일부 방어 기법에 더욱 강한 저항성을 보일 가능성이 있다.

따라서 새로운 모델과 에이전트 환경에서 방어 기법의 효과가 얼마나 지속되는지 검증할 필요가 있다.

#### 다섯 번째, 역공격의 법적·윤리적 문제

공격자의 환경에서 코드 실행을 유도하는 방식은 기술적으로 흥미롭지만 실제 적용에는 법적·윤리적인 문제가 존재할 수 있다.

방어 목적으로 수행하더라도 외부 시스템에 대한 비인가 접근으로 이어질 수 있기 때문이다.

따라서 실제 연구나 프로젝트로 구현할 경우에는 공격자의 시스템을 직접 침해하는 방식보다는 격리된 환경에서 실행 여부를 기록하거나 무해한 경고를 발생시키는 방식으로 검증하는 것이 적절하다고 생각한다.

## 6. 논문을 통해 배운 점과 앞으로의 연구 방향

### 6.1. 논문을 읽고 느낀 점

이전까지 AI 에이전트의 보안 문제를 생각할 때는 주로 프롬프트 인젝션과 같은 공격을 통해 모델의 기존 명령을 무시하게 하거나 의도하지 않은 행동을 수행하게 만드는 방법에 집중하였다.

실제로 AI 에이전트를 대상으로 직접 프롬프트 인젝션과 간접 프롬프트 인젝션을 실험하면서, 외부에서 전달되는 명령이 모델의 행동에 어떠한 영향을 미치는지 확인한 경험이 있다.

그러나 이 논문을 읽으면서 명시적으로 명령을 삽입하지 않아도 에이전트의 행동을 조작할 수 있다는 점이 인상 깊었다.

LLM 에이전트는 스스로 정보를 수집하고 추론하여 행동을 결정한다는 장점이 있지만, 바로 이러한 특성이 공격자가 악용할 수 있는 새로운 공격 표면이 될 수 있다.

특히 잘못된 정보가 에이전트의 지식 구조에 저장되면 해당 정보가 한 번의 응답에만 영향을 미치는 것이 아니라 이후의 여러 판단과 행동에도 지속적으로 영향을 줄 수 있다는 점에서 일반적인 LLM의 보안 문제와 에이전트의 보안 문제는 차이가 있다고 느꼈다.

또한 기존에는 AI를 활용하여 보안 공격을 자동화하거나, AI 자체를 공격하는 방법을 중심으로 생각해 왔다면, 이번 논문을 통해 AI의 취약점을 역으로 이용해 시스템을 보호하는 관점도 고려할 수 있게 되었다.

이러한 관점에서 본 논문의 가장 큰 의의는 개별적인 방어 기법의 제안뿐만 아니라 공격자가 사용하는 AI의 추론 능력 자체를 새로운 방어 대상으로 정의하였다는 점이라고 생각한다.

### 6.2. 앞으로 더 읽어볼 논문

이번 논문을 읽으면서 LLM 기반 공격 에이전트의 내부 구조와 입력 데이터의 신뢰성 문제를 더욱 깊이 이해할 필요가 있다고 느꼈다.

이를 위해 다음 논문들을 추가로 읽어보고자 한다.

#### 1. PentestGPT: Evaluating and Harnessing Large Language Models for Automated Penetration Testing

- 학회: USENIX Security 2024
- 저자: Gelei Deng et al.

본 논문의 주요 평가 대상인 PentestGPT를 제안한 연구이다.

PentestGPT가 정보를 수집하고 지식 구조를 유지하며 공격 단계를 결정하는 방식을 자세히 살펴보고 싶다. 특히 잘못된 정보가 내부 지식 구조에 저장되고 이후 공격 행동에 영향을 미치는 과정을 이해하는 데 도움이 될 것이라고 생각한다.

#### 2. Formalizing and Benchmarking Prompt Injection Attacks and Defenses

- 학회: USENIX Security 2024
- 저자: Yupei Liu et al.

프롬프트 인젝션 공격과 방어를 체계적으로 정의하고 평가하는 연구이다.

기존의 프롬프트 인젝션 방어 기법이 본 논문에서 제안하는 잘못된 정보 기반 기만에도 효과적으로 적용될 수 있는지 비교하고 싶다.

#### 3. Bad Characters: Imperceptible NLP Attacks

- 학회: IEEE Symposium on Security and Privacy 2022
- 저자: Nicholas Boucher et al.

사람이 인식하기 어려운 유니코드 문자를 이용하여 자연어 처리 시스템을 공격하는 연구이다.

본 논문의 LLM 전용 허니토큰 기법과 직접적으로 관련되어 있으며, 인간과 모델 사이의 문자열 인식 차이가 어떻게 보안 취약점으로 이어지는지 추가적으로 공부하고 싶다.

#### 4. Lost in the Middle: How Language Models Use Long Contexts

- 학술지: Transactions of the Association for Computational Linguistics, 2024
- 저자: Nelson F. Liu et al.

LLM이 긴 컨텍스트에서 중요한 정보를 얼마나 효과적으로 활용할 수 있는지 분석한 연구이다.

본 논문에서 제안한 탐색 공간 폭발 및 모델 속도 저하 기법과 연결하여, 불필요한 정보가 에이전트의 작업 선택 및 추론 성능에 미치는 영향을 이해하고 싶다.

### 6.3. 직접 구현하고 재현해보고 싶은 부분

이번 논문에서 가장 먼저 재현해보고 싶은 기법은 프롬프트 인젝션을 사용하지 않고 잘못된 정보를 제공하여 에이전트의 추론과 행동을 변경하는 방법이다.

기존에 진행했던 OpenClaw와 AgentDojo 기반의 AI 에이전트 보안 실험 경험을 바탕으로, 이번에는 명령의 조작뿐만 아니라 외부 정보의 신뢰성에 집중한 실험을 진행해보고 싶다.

우선 공개된 CHeaT 도구와 PentestGPT를 활용하여 격리된 실험 환경을 구축하고, 논문에서 제안한 기법 중 다음 세 가지를 우선적으로 재현할 계획이다.

- T1.1: 가짜 취약점 정보를 제공하여 에이전트의 판단을 왜곡하는 기법
- T4.1: 관련 없는 정보를 대량으로 제공하여 에이전트의 탐색 공간을 증가시키는 기법
- T4.3: 파일 사이의 순환 참조를 구성하여 반복적인 탐색을 유도하는 기법

이후 동일한 작업에 대해 다음 세 가지 실험 환경을 구성하여 결과를 비교해보고 싶다.

| 실험 환경 | 설명 |
| --- | --- |
| Baseline | 어떠한 조작도 적용하지 않은 정상 환경 |
| Prompt Injection | 명시적인 프롬프트 인젝션이 적용된 환경 |
| Misinformation | 명령이 아닌 잘못된 정보가 삽입된 환경 |

이때 단순히 에이전트가 함정에 빠졌는지만 확인하는 것이 아니라 다음과 같은 지표를 함께 측정할 계획이다.

- 에이전트의 공격 또는 작업 성공률
- 작업 완료까지 걸린 시간
- 도구 호출 횟수
- 전체 토큰 사용량
- 동일한 작업의 반복 수행 횟수
- 환각 발생 여부
- 잘못된 정보가 이후 작업에 미치는 영향

추가적으로 방어 정보가 에이전트의 장기기억이나 지식 구조에 저장되었을 때 이후 작업에 얼마나 오랫동안 영향을 미치는지도 분석해보고 싶다.

### 6.4. 다른 분야에 적용할 수 있는 가능성

본 논문은 침투 테스트 에이전트를 중심으로 연구를 진행했지만, 제안된 핵심 아이디어는 다른 분야의 AI 에이전트에도 적용할 수 있을 것이라고 생각한다.

예를 들어 이메일을 읽고 업무를 처리하는 AI 에이전트, 파일을 분석하고 코드를 수정하는 개발 에이전트, 여러 외부 서비스와 상호작용하는 자동화 에이전트 역시 외부 환경에서 수집한 정보를 기반으로 행동한다.

이러한 에이전트는 악성 명령이 포함되어 있지 않더라도 잘못된 정보를 신뢰하는 과정에서 의도하지 않은 행동을 수행할 수 있다.

구체적으로 다음과 같은 환경에 적용할 수 있을 것이다.

| 적용 분야 | 연구 가능성 |
| --- | --- |
| 개발 에이전트 | 잘못된 프로젝트 문서나 의존성 정보를 신뢰하여 부적절한 코드 수정 또는 실행을 수행하는지 분석 |
| 업무 자동화 에이전트 | 가짜 업무 정보나 이메일을 통해 잘못된 의사결정이 발생하는지 분석 |
| AI 기반 보안 관제 | 조작된 로그로 인해 실제 보안 위협을 놓치거나 잘못된 위협을 탐지하는지 분석 |
| 멀티 에이전트 시스템 | 하나의 에이전트가 잘못된 정보를 전달했을 때 다른 에이전트로 정보 오염이 확산되는지 분석 |

반대로 악성 AI 에이전트의 활동을 탐지해야 하는 환경에서는 이러한 특성을 이용하여 에이전트 전용 허니토큰을 구축하거나, 기만적인 정보를 통해 자동화된 정보 수집을 탐지할 수도 있다.

따라서 침투 테스트 환경에서의 기만 기법을 일반적인 도구 사용형 AI 에이전트 환경으로 확장해보고 싶다.

### 6.5. 연구 프로젝트로 발전시키고 싶은 방향

이번 논문을 바탕으로 프로젝트를 진행한다면 다음과 같은 주제로 발전시키고 싶다.

**외부 데이터의 신뢰성 조작에 따른 AI 에이전트의 행동 변화 분석 및 검증 프레임워크 개발**

본 논문이 악성 AI 에이전트를 기만하는 방어 전략에 집중하였다면, 나는 이러한 기만에 취약한 AI 에이전트를 어떻게 더 안전하게 설계할 수 있는지에 대해서도 연구해보고 싶다.

구체적으로는 외부에서 수집한 정보가 에이전트의 지식 구조에 저장되고 이후의 계획과 도구 실행에 반영되는 과정을 추적하고자 한다.

이후 정보의 출처, 신뢰 수준, 기존 정보와의 불일치 여부 등을 검증하는 모듈을 추가하여 에이전트의 행동 변화와 보안 성능을 비교할 수 있을 것이다.

연구를 진행한다면 다음과 같은 단계로 구성하고 싶다.

1. 기존 논문의 기만 기법 및 실험 환경 재현
2. OpenClaw와 같은 일반적인 AI 에이전트 환경에서 정보 기만 실험
3. 잘못된 정보가 에이전트의 기억, 계획, 도구 실행에 미치는 영향 분석
4. 정보 출처 및 신뢰성 검증 모듈 구현
5. 검증 모듈 적용 전후의 보안 성능 및 정상 작업 수행 능력 비교

이때 중요한 것은 모든 외부 정보를 차단하는 것이 아니라, 정상적인 작업 수행 능력을 유지하면서 잘못된 정보의 영향을 최소화하는 것이다.

이를 위해 정상적인 작업 성공률과 기만에 대한 저항성을 함께 측정하고, 정보 검증 과정에서 발생하는 오탐률 및 추가적인 시간 비용도 분석하고 싶다.

## 7. 마무리 및 앞으로의 계획

이번 논문을 통해 AI 에이전트의 보안 문제는 단순히 모델이 악성 명령을 따르는지에 관한 문제에만 국한되지 않는다는 점을 배웠다.

에이전트가 어떤 정보를 신뢰하고, 이를 어떻게 기억하며, 어떠한 판단을 거쳐 실제 행동으로 연결하는지에 대한 전체적인 과정 역시 중요한 보안 연구 대상이 될 수 있다.

특히 공격을 수행하는 AI의 취약점을 역으로 활용하여 시스템을 보호한다는 관점이 흥미로웠다.

기존에 진행했던 AI 에이전트 보안 실험에서는 프롬프트 인젝션을 중심으로 모델의 행동을 조작하는 방법을 분석하였다. 그러나 이번 논문을 통해 직접적인 명령 삽입 없이도 정보 자체를 조작하여 에이전트의 판단과 행동에 영향을 줄 수 있다는 사실을 알게 되었다.

앞으로는 다음과 같은 활동을 진행하고자 한다.

- [ ] PentestGPT 논문을 읽고 다중 LLM 에이전트의 내부 구조 분석하기
- [ ] CHeaT의 공개 소스 코드와 실험 데이터셋 살펴보기
- [ ] 격리된 환경에서 Cloak, Honey, Trap의 대표 기법 재현하기
- [ ] 기존 프롬프트 인젝션과 정보 기만 방식의 효과 비교하기
- [ ] 잘못된 정보가 에이전트의 기억과 이후 도구 실행에 미치는 영향 분석하기
- [ ] 정보의 출처 및 신뢰성을 검증하는 에이전트 보안 모듈 설계하기

이번 논문 리뷰를 단순히 새로운 방어 기법을 이해하는 데 그치지 않고, AI 에이전트가 외부 정보를 신뢰하고 행동을 결정하는 과정에서 어떤 보안 문제가 발생하며 이를 어떻게 검증하고 개선할 수 있는지 탐구하는 출발점으로 삼고 싶다.
